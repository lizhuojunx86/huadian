## 2. 关键元决策（按时间）

### 2.1 "声誉公共品"档位的第一次实测：它在实践中等于零产出（7/20 → 8/16）

ADR-041 §A1 把 huadian 定为"声誉公共品 + 方法论兵工厂"，质量底线写了三条（kb_forge 93 passed 不破 / 真相表照实更新 / 月度日记节律维持）。本月是这个档位落档后的第一个完整周期，实测结果：**三条底线里有两条破了**（真相表 4 周未更新 / 日记节律断档），只有测试底线因为无人改动代码而自然保住。

这里要克制两种读法：

- **不能读成"档位定错了"**。注意力去向是 traceguard 与审计线，而那条线本月产生了本仓三个月都没产生的外部信号——按组合视角这是**正确的资源配置**，ADR-041 §A1 正是为了承认这一点。
- **也不能读成"没关系"**。档位落档时明确写了"质量底线不降"。**降档不等于免检；它恰恰应该提高对"底线三条"的执行密度，因为除此之外本仓不再有别的活。** 实际发生的是相反：档位一降，连底线也一起松了。

**元教训**：把一个项目从"主线"降为"维持"时，真正的风险不是它做得少，而是**"维持"这个词没有可执行的定义**。ADR-041 写了三条底线，但没写"谁在什么节奏上检查这三条"。本次的补救是给真相表加 stale 机制（见 §2.2），但更一般的教训是：**降档 ADR 必须自带一个比在档时更频繁、更机械的检查节律**，否则"维持"会静默滑成"归档"。

### 2.2 §1.2 真相表的新失效模式：不是渲染层盖住判据层，是判据层自己停摆

真相表 6/7 设立时针对的病是"⭐ 叙事系统性盖住对外可验证状态"。本月发现它的第二种失效方式，机制完全不同：**没人写错任何一条，只是没人再去采集。** 结果是这张表连续 4 周描述了一个已经不成立的世界，而且是**双向失真**：

| 方向 | 具体 |
|---|---|
| **高估** | "SSRN 7099138 = case-2 首个公开、可引用、带时间戳的学术制品" —— 表述完全属实，但读者（包括未来的 agent 和我自己）会把它读成"已经产生学术触达"。8/16 实测：上线 36 天，**下载 0，摘要浏览 1**，而那 1 次是本次核查自己产生的。 |
| **低估** | 7/17 以来的外部战果全部产生在 traceguard 仓，一条没回流：发表数 5→12、≥7 项上游修复合入 4 个仓、读者建议 48 小时进代码（kikashy → `7618f1e`）、方法被第三方独立执行（hannune 用它查出自己 pipeline 的同类问题）。 |

**两个方向的偏差同时存在，这件事比任何单向偏差都重要**：它说明"去乐观偏差"这个设计目标本身是不够的。一张只防高估的表，在停止采集后会同时高估旧事实、低估新事实，而它的使用者仍然以为自己在读一张校准过的表。

**本月决策**：建议给真相表加一条**元判据**——"最后采集日 > 21 天则整表标 stale"。它不判断任何一项的对错，只声明这张表当前不可信。**判据体系需要一个关于自身新鲜度的判据。** 此条待下次审计正式并入。

### 2.3 止损线之间会互相矛盾，而解法必须先过 Goodhart 这一关（8/14 触发）

case-2 止损线 S5：距上次 L1 框架代码改动 > 4 周 → 先回 L1 还债。kb_forge 最后改动 7/17，**8/14 触发**。

但 ADR-041 §A3 已在 7/16 把 kb_forge v0.1 **冻结为触发制**：无真实外部使用者不解锁工程化议程。两条治理条文都有效、都是用户批准的、且**不可同时满足**：S5 要求去改 L1，A3 要求不要为了议程去改 L1。

最省事的做法是提交一个小改动把计数清零。**本仓恰恰不能这么做**——方法论 08 与 10 两篇文章的核心论点就是"指标一旦成为目标就不再是指标"，08 §7.3 引的正是 Goodhart。**如果本仓为满足自己的止损线计数而制造一次 L1 提交，那两篇文章的立场就没了**，而它们是 P2 命题的全部资产。

**本次处置**：按 A3 优先；S5 用其条文里原有的另两条还债路径（**公开 push + 外审**）折抵，本批两条都实际执行。S5 措辞修订（"回 L1"→"回 L1 或其冻结期替代路径"）留新 ADR，本次不擅改止损线条文。

**元教训**：止损线是在特定时点、针对特定风险写的；**当上位决策（ADR-041）改变了系统结构，下位止损线不会自动失效，它会带着旧假设继续触发。** 治理体系需要的不只是"新决策覆盖旧决策"，还需要**在写新 ADR 时显式扫描它使哪些既有止损线失去前提**。ADR-041 当时没做这一步——它列了对 ADR-028/031/038 的影响，漏了 case-2 §11 的 S1-S5。

### 2.4 负空间机制的首次实证：它在设立后 1 个月拦下了第一次真实诱惑

ADR-041 §A6 新设"每季度把当前最想做但边际抽象价值存疑的 3 件事写进负空间"，2026-Q3 首批第 ② 项是**"为 SSRN 下载量做投放优化"**。

本月实测 SSRN 下载 0，这**正是该条目预设的诱因**——看到 0 下载，最自然的反应就是去做投放。按条文，本次**不启动任何投放动作**。

值得记的是 A6 的设计为什么有效：它不是在诱惑出现时才判断（那时判断力最差），而是**在冷静期预先把诱惑写下来并署名**。这和 case-2 止损线是同一类机制，但 A6 补上了止损线缺的那一半——止损线防的是"做得太深"，负空间防的是"做了不该做的方向"。

同时要记一条**反向的诚实**：本次不投放，不等于零下载没有信息。它证伪的是"预印挂出即产生触达"，保留的是"预印作为可引凭据"的功能——后者在 7/17 两封外审信里已经用上了。**把预印的角色从"触达工具"精确到"凭据"，这是本月唯一一个被数据推动的定义修正。**

### 2.5 三路探针全零 vs 仓外多点开花：不是两条线的优劣，是兑现周期的差

8/16 补做的 7/25 三路信号回收（逾期 22 天）：SSRN 下载 0 / 蒲公英回帖 0 / 外审回复 0（发出 30 天）。同期仓外审计线：≥7 项上游修复合入、读者建议 48 小时进代码、方法被第三方独立执行。

**克制读法**：这不是"学术线错了"。学术制品的兑现锚在 2026-09 外审与 2026-10 v1.0，用 8 月的读数判它的死刑属于用错时间尺度。但有一件事确实需要修正——ADR-041 §A5 登记 case-2 公开制品为"医药商业线信任资产"，对应"用公开研究替代客户案例"这一招。**这一招真正需要的是"被人用过的研究"，不是"被发表的研究"。** 本仓登记的三件资产，8/16 实测触达合计约等于零。

因此本月给 §12 桥接登记表加了"实测触达"补注，并明确禁止把"已发布"读作"已触达"。**登记表如果只记录制品是否存在，它就会重复真相表刚刚犯过的错。**

### 2.6 一个待决而非已决的事：2026-09 外审窗口只剩两周，确认审稿人 0 人

三篇 v0.4 的 author-side 四项在 6 月已全部完成，剩下的全部依赖外部审稿人。7/17 发出两封冷邮件，30 天 0 回复；约定的第 3 周 bump 逾期 9 天（本批已备稿）。

**本篇不替用户决策，只把选择显式化**：9 月外审窗口开启时若仍无审稿人，是（a）按 author-side 状态直接发 v1.0、（b）顺延等外审、还是（c）改走"预印 + 公开评议"路径。**最坏的情况不是选错，是不选**——锚点静默滑过，然后在某次审计里被发现"2026-10 v1.0 未达成"，而没有任何一份文档记录过它是被谁、在什么时候、基于什么放弃的。这正是 7 月审计抓到的 governance-as-ratification 的下一次复发形态。

## 3. 元反思 — 当一个项目的主要功能变成"记录"

前三篇日记记的都是"在做事的过程中作出的决策"。本篇覆盖的窗口里本仓没有产出，于是本篇的内容几乎全是关于判据、登记、止损线、负空间——**关于治理装置本身的**。

这不是本篇的写法问题，是事实的形状：**本仓当前的实际功能已经是"登记与判据"，不是"产出"。** 按 ADR-041 的档位这是可以接受的，但需要显式承认，因为它改变了"什么算本仓的好月份"——一个好月份不再是"推进了多少"，而是"判据是否照实、登记是否及时、止损线是否没被绕过"。

如果这个定义成立，那么本月按新定义算是**及格偏下**：三条底线破了两条，但破了之后在同一个月内被发现并补齐，且补齐的过程产出了三条可复用的机制建议（真相表 stale 元判据 / 降档 ADR 自带检查节律 / 新 ADR 须扫描其使哪些止损线失去前提）。**机制建议是本月唯一的新知识资产**，也是本篇之所以值得写的理由。
